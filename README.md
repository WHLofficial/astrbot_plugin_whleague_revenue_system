# 主场营收系统（WHL 球队主场系统）

按真实联赛轮次运行的**辅助工具**：赛程导入 → 天气预报 → 赛果录入 → 上座/票房自动计算 → 赛季统计；
另含球场建设（管理员导入）、死忠球迷演化、档期活动、冠名权、随机事件（即发/选择型，支持 LLM 文案与设计）。

**定位**：插件只负责本系统内的收支记账（收入/支出数字是联赛经济决策的参考项），不接球员工资、
不闭环联赛经济。所有数值均可通过 `/主场设置` 调整，不依赖改代码。

---

## 一、核心工作流（管理员按轮次操作）

```
① /主场赛程导入       每行：轮次 主队 客队 [周] [天] [时间]（可附带 xlsx/csv 文件）
② /主场天气 <轮次>    轮前掷天气并存档（可覆盖：/主场天气 <轮次> <主队> <天气>）
③ /主场赛果 <轮次>    轮后录入胜/平/负 [比分] → 自动计算该场上座/票房/商业/转播并记账（可附带文件）
④ /主场轮次统计 /主场赛季统计   查看统计（S8 汇总样式）
⑤ /主场推进窗口 /主场推进赛季   推进节奏（机制同谈判插件）
⑥ /主场属性 <队名> [影响力] [容量] [等级]   属性变更自动按定价记账（批量可附带文件）
⑦ /主场事件 [队名] [事件id]   管理员触发随机事件（即发立即生效；选择型广播选项待球员定夺）
⑧ /主场结算 [强制]    窗口末：维护费+档期兑现+冠名费+死忠演化+选择事件兑现 → 账本 → 摘要
                     （「强制」= 撤销上次结算流水并重算，死忠演化不重复执行）
⑨ /主场轮次统计图 <轮次> /主场赛季走势图   生成统计图（展示工作表风格，全体群友可查）
```

**轮次支持文字前缀（赛事）**：轮次字段可以是「顶级9」「次级11」「冠军3」「小组赛第3轮」
等（前缀识别赛事，默认「联赛」）。次级/顶级/冠军杯可同轮次同窗口共存互不干扰；
天气/赛果/统计/图表命令的轮次参数均支持该写法。前缀映射可用
「/主场设置 competition_aliases」调整（JSON：赛事名→前缀列表）。

**赛程行可选字段**：`轮次 主队 客队 [周] [天] [时间]`——周=周次（W12 或 12）、
天=星期数字 1-7（D6 或 6）、时间=开球 HH:MM；星期由天自动生成单字（1→一 … 7→日）。
例：`1 利物浦 巴塞罗那 W12 D6 15:00`；只写时间可 `1 利物浦 巴塞罗那 15:00`。
**赛果行可选比分**：`主队 胜/平/负 [比分]`，如 `利物浦 胜 2-1`（支持 0-0PK2-4 等自由文本）。

### 文件批量导入（xlsx / csv）

`/主场赛程导入`、`/主场赛果 <轮次>`、`/主场属性导入` 三个命令在群里**附带 .xlsx / .csv 文件**即可走文件导入（无附件时仍按文本粘贴）。文件规则：

- 首行可带表头（轮次/主队/客队、周/天/星期/时间、主队/赛果/比分、队名/影响力/容量/等级 等关键字自动识别列序），无表头则按位置取列
- CSV 自动识别编码（utf-8-sig → gbk → utf-8），支持逗号或制表符分隔；xlsx 读取第一个工作表
- 赛程文件可跨多轮；轮次列支持「顶级9」「次级11」等文字前缀，周/天/时间列可选（星期列忽略，自动生成）；赛果文件一文件一轮（轮次由命令指定），比分列可选
- 非法行列跳过并逐行报错，其余继续导入；文件大小上限默认 20MB（`import_max_file_size_mb`）
- 下载的临时文件解析后自动删除

## 二、上座与收入公式（逐场，录入赛果时计算）

- **死忠球迷** = 影响力 × 20（影响力由管理员按窗口导入，与阵容绑定，转会可能导致下降）
- **上座** = min(容量, 死忠 × 上座倍数 × 等级系数 × 战绩系数 × 天气系数 × 对手系数 ± 3%)
  - 上座倍数 = 4 × (1 + 0.35×等级)：0级×4.0 … 4级×9.6（扩建杠杆）
  - 等级系数 ×1.0~×1.4；战绩系数按近 3 场真实 Pts（胜3平1负0）查表 ×0.7~×1.25，自动算
  - 天气系数：晴 1.05-1.25 / 多云 0.90-1.04 / 雨 0.80-0.89 / 雪 0.75-0.79（S8 表比例拉伸）
  - 对手系数 = 1 + 5%×客队影响力/主队影响力
- **票房** = 上座/万 × 1.5M + 上座/万 × 0.1M×商业区级；**转播** = 0.3M×灯光级/场
- **维护费**（窗口结算）= 等级基础 + 每万座费率 × 容量(万) × 该窗口主场场次（按容量收，空座照养）

## 三、球场等级表（S9 规则）

| 级 | 名称 | 座位范围 | 半赛季基础维护 | 每万座/主场 | 上座系数 | 升级费 |
|---|---|---|---|---|---|---|
| 0 | 社区级 | 1.2-2.5万 | 2.00M | 0.80M | ×1.0 | 3.0M |
| 1 | 地区级 | 2.0-3.5万 | 5.00M | 0.55M | ×1.1 | 4.5M |
| 2 | 大区级 | 2.5-4.5万 | 8.00M | 0.35M | ×1.2 | 6.0M |
| 3 | 国家级 | 3.5-6.0万 | 11.00M | 0.28M | ×1.3 | 10.0M |
| 4 | 国际级 | 5.0-10.0万 | 14.00M | 0.20M | ×1.4 | — |

- 扩建：100 座为单位，0.1M/100 座（10M/万座），只能在当前等级座位范围内
- 升级需容量 ≥ 新等级下限；`max_open_tier` 控制开放进度（S9 初仅开放 0→1）
- 属性导入自动记账（扩建/升级支出进账本），25% 以**建设券**返还（仅可抵扣后续建设支出）

## 四、子设施（管理员导入等级 0-5）

| 设施 | 效果 |
|---|---|
| 商业区 | 比赛日每万上座 +0.1M/级 |
| 灯光转播 | 每主场 +0.3M/级 |
| 草皮 | 草皮损坏事件概率 ×(1−0.15×级)；演唱会收益 +10%/级 |
| 青训中心 | 死忠成长速率 +3%/级 |
| 医疗中心 | 负面事件金额 −5%/级 |

## 五、死忠球迷演化（窗口结算时执行，非对称）

- 目标 = 本窗口影响力 × 20；初始满目标；上限默认 10,000
- **涨粉**：靠拢 = 差额 × 50% × (0.6 + 0.4×上座率)——热闹球场涨粉快
- **掉粉**：靠拢 = 差额 × 50% × (1 + 0.8×(1−上座率))——越空跑得越快
- 修正：近 3 场 Pts ≥7 → +5%、≤1 → −5%；球迷开放日 +5%；随机事件 ±
- 影响力下降（如转会卖人）后掉粉滞后约两窗口兑现，覆盖额度随之缩水，大球场自然流血

## 六、档期活动（玩家每窗口 2 档）

`/球场活动 <类型> [档位]`：演唱会（3-8M，15% 概率草皮损坏追加维护）/ 电竞（2-4M）/
球迷开放日（0.5M+死忠5%）/ 青训夏令营（1M×(1+青训级加成)）/ 空置。

## 七、冠名权（玩家）

`/冠名 <品牌>` / `/退冠名`：报价/窗口 = (0.5 + 0.3×容量万 + 0.12×死忠万) × 热度；
合同默认 4 窗口；提前解约赔付剩余 30%；单窗口死忠跌 ≥30% 时品牌有概率主动解约；
球场显示名变为「品牌·球场名」。

## 八、随机事件（管理员触发）

**两类事件**：内置 22 条 × 8 类（天气衍生/场地故障/球迷舆情/商业机会/媒体/档期联动/冠名联动/意外之财）。

- **即发型（6 条）**：触发即生效——金额/维护入账、死忠变动、影响下一场上座；文案默认由 **LLM 生成**（失败回退模板）。
- **选择型（16 条）**：多数事件是「玩家在多项操作中任选其一」，每项操作带**正面/负面概率表**
  （结算时按所选选项的概率掷骰，未定按最差兜底）。触发时只发 **LLM 叙述广播 + 选项列表**（
  **不显示概率**，给教练留悬念）并进入「待定」，不立即记账。

### 玩法闭环（生成 → 广播 → 收集 → 导入 → 结算）

```
① /主场事件               全员分配（每队独立命中，默认 40%，部分队不被分配到）
② /主场事件 <队名> [事件id]   指定单队（可选事件id 强制）
   即发型 → 立即出结果；选择型 → LLM 叙述广播 + 选项列表（无概率），进入「待定」
③ /主场事件选择列表        查看当前窗口全部待定/已选/已结算状态
④ 玩家在群里按广播回应：队名 事件名 选项号（如：利物浦 周边爆款 ①）
⑤ 管理员统一导入：
   /主场事件选择 <队名> <事件名> <选项号>      单条录入
   /主场事件选择导入                            批量（多行「队名 事件名 选项号」，支持 ①②③④）
⑥ /主场事件结算 [全部]      （可选）提前结算，不必等窗口结算：
   默认只结已导入选择的（按所选选项概率掷骰）；加「全部」连未定的一并按最差兜底
⑦ /主场结算                窗口末统一结算：把剩余未定的选择自动按最差结果（净额 = 资金−维护）执行
   （「/主场结算 强制」重算时选择事件只重记账目流水，死忠/上座等状态沿用，不重复叠加）
```
每个已结事件都会写一行**结算短文案**（LLM 生成，失败回退确定性摘要），在结算回顾中显示。
广播（叙述段）与结算结果文案默认都由 LLM 生成，失败自动回退模板/摘要。

**LLM 设计（管理员采纳后才生效）**：
- `/主场事件生成 <数量> [主题]` → `/主场事件列表` → `/主场事件采纳 <id>` / `/主场事件丢弃 <id>`
- LLM 可产出即发与选择型草稿；草稿数值会被钳制（金钱 ≤8M、死忠 ≤5%、维护 ≤5M）；
  选择型自动校验：2~4 个选项、每个选项 ≥2 条概率结果并归一、每项至少一条正面与一条负面路径；
  破坏经济的草稿不可能生效
- LLM 无内容/失败会自动**重试一次**并按原因写日志（provider 未选用 / 空内容 / 超时一目了然）；
  长 prompt（事件设计）建议把 `llm_timeout_seconds` 调大（默认 60s）
- 事件广播（叙述段）与结算结果短文案由 LLM 生成，失败自动回退模板/确定性摘要
- 手写：`/主场事件写 <名称> <类别> <权重> <effectsJSON>`（即发，如 `{"money": 3}`）
  或 `/主场事件写 <名称> <类别> <权重> choice <选项JSON>`
- `/主场品牌生成 / 主场品牌列表 / 主场品牌采纳 / 主场品牌丢弃` 逻辑不变

## 九、统计图（全体群友可查）

风格参照 S8 计算器「展示」工作表：微软雅黑、细网格线、千分位数字、PNG 原图发送。
**赛事配色**（与展示表一致）：次级联赛=薰衣草紫 #B19CD9、顶级联赛=橙 #E97132、
其余（联赛/冠军杯/未知）=绿 #5CB48E。

- `/主场轮次统计图 <轮次>`：该轮已录赛果的主场比赛表格，列序对齐展示表：
  `周(W12) | 天(D6) | 星期(六) | 时间(15:00) | 天气 | 主队 | 比分(2-1 胜) | 客队 | 球场 | 观众人数 | 上座率`
  + 合计/场均。按赛事各出一张图，轮次参数支持前缀（如「顶级9」出橙色图、「次级11」出紫色图）；
  标题格式与「展示」表一致（WHL 第X赛季XX联赛现场观众统计（第N轮））
- `/主场轮次预告图 <轮次>`：**上半为对阵表、下半为天气预报**合成一张图（赛前预览用）；
  对阵含 周/天/星期/时间/主队/客队/球场，天气按预报着色（晴橙/多云灰/雨蓝/雪浅蓝），
  未预报显示灰色「待预报」；轮次参数同样支持赛事前缀
- `/主场赛季走势图`：各队本赛季主场观众折线图（横轴为该队第几次主场，图例按场均上座排序）
- 生成图片存于数据库同级 `charts/` 目录，超过 50 张自动清理最旧；
  依赖 Pillow，中文字体按「系统字体（微软雅黑等）→ 插件内置 Noto Sans SC → 字体目录扫描」
  自动查找——云服务器/容器无需另装字体；也可 `/主场设置 chart_font_path` 指定字体文件

## 十一、与谈判系统的联动

- 只读谈判系统数据库（`negotiation_db_path` 配置，留空自动探测）：球队列表、QQ↔球队绑定
- 玩家命令通过绑定关系定位自己的球队；谈判库不可用时自动回退纯管理员模式
- 赛季/窗口节奏由本插件独立维护（`/主场推进窗口` 与谈判插件的 `/进入下个窗口` 各自推进）

## 十二、配置与数据

- 配置：WebUI（`_conf_schema.json`）或 `/主场设置 <键> <值>`；`/主场查看配置` 查看
- 数据库：`plugin_data/astrbot_plugin_whleague_revenue_system/revenue_system.db`
  （WAL 模式；每日 04:00 自动备份至 backup/ 目录，保留份数可配）
- v2 起 matches 表新增赛事列（轮次文字前缀识别），v3 起新增 比分/周/天/时间 四列，
  v4 起 window_summaries 记录结算流水 ID（供「强制」重算精确撤销），
  v5 起 event_pool 新增 event_type/options_json（即发 vs 选择型）并新增 event_choices 玩家决策表；
  旧库启动时自动迁移（数据保留，比赛标记为「联赛」，新列留空，旧事件默认即发型）
- 主要配置项：死忠系数、演化速率、上座倍数、票收基准、等级表、天气概率/区间、战绩系数表、
  冠名报价系数、赛事前缀映射（`competition_aliases`）、文件导入大小上限（`import_max_file_size_mb`）、
  LLM 开关（`llm_flavor_enabled`/`llm_design_enabled`）、图表字体路径（`chart_font_path`）等

## 十三、开发

```
python tests/run_all.py    # 86 项零依赖测试（astrbot 桩 + 临时数据库 + LLM 桩）
```

目录结构照搬谈判系统分层惯例：`main.py`（薄命令层）→ `handlers/` → `services/` →
`db/{connection,schema,dao}` + `config/` 双轨 + `utils/`。
